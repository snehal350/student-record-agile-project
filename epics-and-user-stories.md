# Epics and User Stories

User stories below are proposed examples derived from the seven epics in the Unit 2 assignment. Adjust them to match your team's agreed scope.

## Epic 1 — Student Management
**Purpose:** Maintain accurate student records.

- **US-01 — Add student:** As an administrator, I want to register a student so that their academic record can be maintained.
- **US-02 — Search student:** As an authorized staff member, I want to search by student ID or name so that I can find a record quickly.
- **US-03 — Update student:** As an administrator, I want to update student details so that records remain current.
- **US-04 — Delete/deactivate student:** As an authorized administrator, I want to deactivate an obsolete record so that it is not used incorrectly.

## Epic 2 — Course Management
**Purpose:** Maintain course information and student-course assignments.

- **US-05 — Add course:** As an administrator, I want to create a course so that it can be assigned to students.
- **US-06 — Update course:** As an administrator, I want to update course details so that the catalogue remains accurate.
- **US-07 — Assign students:** As authorized staff, I want to assign students to a course so that enrolments are recorded.
- **US-08 — View course details:** As a user with permission, I want to view course information so that I understand the course offering.

## Epic 3 — Attendance Management
**Purpose:** Record attendance and provide attendance visibility.

- **US-09 — Record attendance:** As a faculty member, I want to mark attendance for a course and date so that attendance records remain accurate.
- **US-10 — View attendance:** As a faculty member, I want to view saved attendance so that I can verify records.
- **US-11 — Attendance report:** As authorized staff, I want to generate an attendance report so that attendance can be reviewed.

## Epic 4 — Marks and Academic Performance
**Purpose:** Maintain marks and communicate academic results.

- **US-12 — Enter marks:** As a faculty member, I want to enter marks for students so that performance is recorded.
- **US-13 — Update marks:** As an authorized faculty member, I want to correct marks when permitted so that errors can be resolved.
- **US-14 — Calculate grades:** As a faculty member, I want grades calculated according to approved rules so that grading is consistent.
- **US-15 — Generate result sheet:** As academic staff, I want to generate a result sheet so that results can be reviewed or published.

## Epic 5 — Authentication and Security
**Purpose:** Restrict access to authorized users.

- **US-16 — Login:** As a registered user, I want to log in securely so that I can access permitted functions.
- **US-17 — Logout:** As a user, I want to log out so that my session is not left open.
- **US-18 — Password reset:** As a user, I want to reset my password through a verified process so that I can regain access.
- **US-19 — Role-based access:** As an administrator, I want permissions assigned by role so that users only access authorized functions.

## Epic 6 — Notifications
**Purpose:** Inform relevant users about important academic events.

- **US-20 — Attendance alert:** As a student, I want an attendance alert when a defined threshold is reached so that I can take corrective action.
- **US-21 — Examination notification:** As a student, I want examination notifications so that I can prepare on time.
- **US-22 — Result notification:** As a student, I want to be notified when results are available so that I can view them.

## Epic 7 — Reporting
**Purpose:** Provide useful summaries from academic records.

- **US-23 — Student report:** As academic staff, I want a student report so that I can review student details.
- **US-24 — Performance report:** As faculty, I want a performance report so that I can review marks and grades.
- **US-25 — Course report:** As an administrator, I want a course report so that I can review course enrolment information.
- **US-26 — Academic analytics dashboard:** As an administrator, I want a summary dashboard so that I can identify broad academic trends.

## Story format
Each story follows: **As a [user], I want [capability], so that [benefit].**

Stories should be refined with stakeholders before implementation. These are initial backlog candidates, not proof of completed features.
