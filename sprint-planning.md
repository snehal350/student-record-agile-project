# Sprint Planning and Sprint Backlog

Proposed plan for a student mini-project. Sprint length: two weeks, subject to the course deadline and team availability. Story points are illustrative estimates and should be agreed by the team.

## Sprint 1 — Project foundation and authentication
**Goal:** Establish the project structure and define a secure access flow.

Candidate work:
- US-16 Login — 5 points
- US-17 Logout — 2 points
- US-19 Role-based access — 8 points
- Repository setup and basic interface — task, estimate by team
**Expected deliverable:** Reviewed project setup and an agreed authentication/access-control design or working increment, depending on implementation scope.

## Sprint 2 — Student management
**Goal:** Support the core student-record workflow.

Candidate work:
- US-01 Add student — 5 points
- US-02 Search student — 3 points
- US-03 Update student — 3 points
- US-04 Delete/deactivate student — 5 points
**Expected deliverable:** Student record workflow that meets its acceptance criteria.

## Sprint 3 — Course and attendance
**Goal:** Connect courses with attendance recording.

Candidate work:
- US-05 Add course — 3 points
- US-06 Update course — 3 points
- US-07 Assign students — 5 points
- US-09 Record attendance — 8 points
- US-10 View attendance — 3 points
**Expected deliverable:** Course and attendance workflow.

## Sprint 4 — Marks and reports
**Goal:** Record academic performance and produce basic reports.

Candidate work:
- US-12 Enter marks — 5 points
- US-13 Update marks — 3 points
- US-14 Calculate grades — 5 points
- US-15 Generate result sheet — 5 points
- US-11 Attendance report — 5 points
**Expected deliverable:** Marks/results workflow and basic attendance report.

## Later release candidates
- US-18 Password reset
- US-20 Attendance alert
- US-21 Examination notification
- US-22 Result notification
- US-23 Student report
- US-24 Performance report
- US-25 Course report
- US-26 Academic analytics dashboard

## Sprint planning checklist
- Confirm the Sprint Goal.
- Select stories based on priority and actual capacity.
- Check dependencies and acceptance criteria.
- Break stories into tasks.
- Agree what “Done” means.
- Revisit scope if capacity changes.

The planned work is not a record of completed work. Update it after each actual sprint.
